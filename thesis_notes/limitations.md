# Limitations

### Implementation design differences from the original algorithms — 2026-06-03

- **Context:** Both EP and DiscoGP are re-implemented inside AutoCircuit's `PatchableModel`/wrapper infrastructure rather than each paper's bespoke codebase. Audited the ports against the original repos (`princeton-nlp/Edge-Pruning` @ `a918efd`, `frankniujc/disco_gp` @ `54aef81`). The cores are faithful; the differences below are deliberate adaptations or known gaps and should be stated as limitations.
- **Observation — common to both ports:**
  - **Single training run is faithful — the curve-tracing difference is evaluation-side, not a faithfulness gap.** EP and DiscoGP (like EAP) estimate edge importance from *one* optimization run; that run's continuous mask **is** the algorithm's native importance output, so returning it as `PruneScores` matches how each method decides which edges to keep — it is not a shortcut. AutoCircuit's `run_circuits` then traces the sparsity–faithfulness curve by top-k thresholding that single ranking (so the port's circuits are strictly nested). The EP paper instead runs independent per-target-sparsity training runs (`ioi_sweep.sh` bash loop; **no merge** — each checkpoint evaluated separately into one scatter point), so its circuits need not be nested. EP provides **no** mechanism to merge multiple runs; ACDC is the only algorithm that synthesizes a ranking across runs (~20 τ-values) and only because its per-τ output is a *binary* circuit with no continuous scores. The lone genuine design choice is the calibration of EP's single run via `target_edge_sparsity=1.1` (a tunable lever) — not whether single-run is correct, which it is.
  - **Pre-composed masks vs. sequential forward-pass masking.** AutoCircuit's wrapper applies one effective mask per edge before patching; the originals thread edge (and EP node) masks sequentially through the forward pass. Same intended math, possibly different gradient dynamics.
- **Observation — Edge Pruning specifics:**
  - **Faithful**: hard-concrete L0 sampling (temp 2/3, stretch [−0.1, 1.1]), `KL(full ‖ circuit)` direction, resample/interchange ablation, Lagrangian `λ₁(s−t)+λ₂(s−t)²` with λ maximized, node-mask composition `1−(1−z_e)(1−z_n)` ≡ paper's `z_edge·z_node`, all run-script LRs = 0.8, `steps=3000`, `sparsity_warmup_steps=2500`, `target_node_sparsity=0.72`, and **`weight_decay=0.01`** (matches the original, which relies on `torch.optim.AdamW`'s default; setting 0 departs from the paper and breaks learning).
  - **Aligned 2026-06-03**: added `warmup_steps=200` to the EP registration to match the original's `--warmup_steps 200` LR warmup (previously defaulted to 0).
  - **Remaining gaps**: KL is computed at the last-token `out_slice` rather than the original's answer-span `[start:end]` (near-identical for single-token IOI); the four original LR groups (edge/node × log_alpha/λ) are collapsed to two shared knobs (no effect at the paper's all-0.8 values, but cannot reproduce edge≠node LR runs).
- **Observation — DiscoGP specifics (edge-only scope):**
  - The thesis uses DiscoGP **edge-only** (`use_weight_masks=False`); the weight-pruning phase and the paper's neuron-level "flexible granularity" are not exercised, so DiscoGP here is not the paper's full joint method.
  - **Faithful** for the edge-only path: `gumbel_sigmoid` + `schedule_epoch_lambda` (verbatim), all edge-phase defaults, zero ablation, Q/K/V-split edges, and the `answer_margin_ce` faith/completeness losses.
  - The default `loss_mode="argmax_ce"` is a port-introduced, task-agnostic relaxation with no counterpart in the original; only `DISCO_GP_EDGE_ONLY_PAPER_PRUNE_ALGO` (`-EP`) uses the paper-faithful `answer_margin_ce`.
  - The `-E` vs `-EP` registrations now differ **only** on `loss_mode` (argmax_ce vs answer_margin_ce); both hold `e_lambda_complete_init=1.0`, so the contrast cleanly isolates the loss-form axis.
- **Significance:** These are the caveats that bound how directly the thesis's EP/DiscoGP numbers map onto the original papers' reported results. Running each gradient method once is faithful to how it estimates importance *and* makes the multi-algorithm comparison apples-to-apples on a shared edge-count grid; the genuine caveats are the items above (ablation type, loss form, KL span, single-run calibration). Ties into the broader non-identifiability framing (Méloux 2025) and ablation-relativity framing (Miller 2024).
- **Code pointer:** `docs/related_work/edge_pruning.md`, `docs/related_work/disco_gp_sheaf_discovery.md`, `auto_circuit/prune_algos/edge_pruning.py`, `auto_circuit/prune_algos/disco_gp.py`, `auto_circuit/prune_algos/prune_algos.py`

### EP port ranks edges identically to the original; the divergence is *where* the threshold applies — 2026-07-23

- **Context:** Midterm appendix prep (limitations slide). Checked the suspicion that the port diverges because the original Edge Pruning emits a binary mask while AutoCircuit needs continuous `PruneScores`.
- **Observation:** The suspicion is not borne out for the ranking. The original's `deterministic_z_from_log_alpha` (`src/modeling/l0.py`) computes `sigmoid(log_alpha / TEMPERATURE * FACTOR)` (`T = 2/3`, `F = 0.8`) and then zeroes the lowest `num_zeros` entries by **top-k on that same soft mask**; `num_zeros` comes from the expected L0 of the stretched-concrete distribution. The port returns `1 - sigmoid(log_alpha / T * F)`, which equals the original's soft mask once the sign-flipped AutoCircuit convention (`z=1` = ablated) is undone, and `auto_circuit/utils/l0_utils.py:15-19` carries the identical constants.
  - So both rank edges by the same monotone function of `log_alpha`, and top-k over the port's `PruneScores` selects the same edge set as the original's own thresholding. The original's `apply_one` binarization is immaterial because `run_circuits` binarizes by threshold anyway.
  - The correct statement is therefore *not* "they emit a binary mask, we emit scores, so the masks diverge" — the binary mask is produced by thresholding exactly the quantity the port exports.
- **Three real divergences, replacing that framing:**
  - **Threshold scope (new, not previously recorded):** the original calls `deterministic_z_from_log_alpha` per `log_alpha` tensor, so `num_zeros` is allocated per tensor from that tensor's own expected L0. AutoCircuit's `run_circuits` thresholds **globally** across all modules. At a matched total edge count the per-module allocation can differ whenever learned sparsity is uneven across modules.
  - **Operating point:** EP's reported circuit size comes from its learned expected sparsity; AutoCircuit's comes from the edge-count grid, so EP's own published circuit is generally not a point on the port's curve.
  - **Node-mask composition:** the port folds node ablation into the per-edge score (`edge_z = 1 - (1 - edge_z)(1 - node_z)`), changing the ranking relative to edge `log_alpha` alone, whereas the original thresholds the node and edge mask families separately. This is larger than the audit's "pre-composed vs sequential" wording suggests, since it affects edge *selection*, not only gradient dynamics.
- **Significance:** Removes a suspected correctness gap (ranking is faithful) and replaces it with a sharper, previously unrecorded one (global vs per-tensor thresholding). Bounds how directly the port's curves map onto EP's published operating point.
- **Open:** the magnitude of the threshold-scope divergence depends on how many `log_alpha` tensors `src/modeling/modeling_fpt2.py` creates; not yet verified. `docs/related_work/edge_pruning.md` §Remaining gaps should gain this item.
- **Code pointer:** `auto_circuit/prune_algos/edge_pruning.py:453-484` (score extraction), `auto_circuit/utils/l0_utils.py:15-19,67` (constants + soft mask); original `src/modeling/l0.py`.

### ACDC's faithfulness curve is coarse and cannot reach small circuits — a tie-block artifact, not a bug — 2026-07-23

- **Context:** Reading the IOI faithfulness figure (`resample discovery · resample eval`), ACDC shows only ~5 points and its first non-zero point sits at ~600 edges, far to the right of every other algorithm, which start at x=1. Checked whether this is a plotting/thresholding artifact.
- **Observation:** It is intrinsic to how ACDC produces `PruneScores`, not a plotting bug. ACDC does **not** score edges individually — it runs the greedy prune loop once per τ and assigns **every edge removed at that τ the same score** (`ACDC.py:173`); edges never removed keep `init_val=t.inf`. With the registered config (`tao_bases=[1]`, `tao_exps=range(-6,-2)`, `prune_algos.py:153-160`) that is only **4 τ values → 5 distinct score levels**. `edge_counts_util` detects the low unique count (`< min(n_edges/2, 100)`) and switches to `EdgeCounts.GROUPS` (`graph_utils.py:465-484`), so the only expressible x-positions are the cumulative tie-block boundaries.
  - IOI resample levels: `inf`×604, 1e-3×1441, 1e-4×4825, 1e-5×9870, 1e-6×15751 → x-points `[0, 604, 2045, 6870, 16740, 32491]`. The first non-zero point = the `inf` core (604 edges), which is why the curve begins beside the GT star (~600) and nowhere smaller.
  - The floor is structural: `run_circuits` binarizes by `abs(score) >= threshold` (`prune.py:94`) and thousands of edges share each score, so a threshold landing inside a tie-block admits the **entire** block. There is no ranking *within* the `inf` core to sub-select from, so ACDC cannot express any circuit smaller than the edges it deems indispensable at every τ.
  - Pattern holds across all 9 ACDC cells (IOI/GT/Docstring × zero/resample/mean): 3 or 5 levels each; first point = core size, ranging 166 (GT resample) to 4048 (IOI zero) edges. Zero ablation always yields the largest core (more edges look indispensable under zero).
- **Contrast:** EAP/EP/DiscoGP emit ~all-unique scores, so `edge_counts_util` uses `LOGARITHMIC` spacing and places points at 1,2,5,10,20,… — a smooth curve from x=1. The asymmetry is a property of ACDC's binary-per-τ output (the same property that lets it, uniquely, synthesize a cross-run ranking), not of the discovery ablation.
- **Significance:** A genuine methodological asymmetry for the faithfulness spine: ACDC's curve cannot enter the small-circuit regime where the optimization-based methods are evaluated, so a head-to-head comparison below the ACDC core size is undefined for ACDC. Reading its curve as "worse at few edges" would be a category error — it has no few-edge points to be worse at.
- **Two levers, corrected 2026-07-27:** the number of distinct τ sets the *number* of points; the *largest* τ sets the left endpoint. The core is exactly the edges surviving the largest τ tested, so raising max τ (not merely adding more τ at the same range) is what lowers the endpoint. The old config's max τ was `1e-3`; see the 2026-07-27 entry for the widened sweep.
- **Code pointer:** `ACDC.py:170-176` (per-τ shared score), `prune_algos.py:153-160` (τ config), `graph_utils.py:461-484` (GROUPS switch), `prune.py:86-98` (threshold binarize).

### ACDC τ sweep widened; ACDC greedy is non-deterministic run-to-run; τ passes are parallelizable — 2026-07-27

- **Context:** To add points to the coarse ACDC faithfulness curve and reach sparser circuits (prev. entry), widened the τ sweep and built tooling to parallelize the (now slower) discovery. All numbers below predate the concurrent batch-size change to the spine (see [[dataloader-consumption-per-algo]]), so specific edge counts will move; the mechanisms hold.
- **Config change (`prune_algos.py` `ACDC_PRUNE_ALGO`):** `tao_bases=[1]`, `tao_exps=range(-6,-2)` (4 τ, max `1e-3`) → `tao_bases=[1,3,5,7,9]`, `tao_exps=range(-5,-1)` (20 τ, max `9e-2`). This is AutoCircuit's own default sweep. Gives ~20 curve points instead of ~5 and, via the larger max τ, pushes the left endpoint below the old ~600-edge core.
- **Cost:** ~5× the old ACDC discovery time (one greedy sweep over all ~32k edges per τ). Measured under the *pre-batch-change* config: docstring (attn-only-4l) ~9 min/cell; GT ~2 h/cell; **IOI ~13 h/cell** (~14 edges/s → ~39 min/τ × 20) — the long pole. (These will change with the new batch size.)
- **ACDC is not bit-reproducible.** Two identical single-process runs (docstring/resample, same seed, same node) differ by **max 0.027 in score and 546/1281 edges**. ~~Cause: the greedy test `faith - prev_faith < tao` (`ACDC.py:170`) is a hard threshold, so GPU floating-point nondeterminism near the boundary flips keep/remove decisions, which cascade through the greedy sweep.~~ **Erratum (2026-08-01): the GPU-FP attribution is wrong.** The dominant cause is non-canonical set-iteration order changing ACDC's greedy visit order between processes; see [[#run-to-run-nondeterminism-is-set-iteration-order-not-gpu-floating-point--2026-08-01]]. The conclusion (ACDC is not bit-reproducible, a caveat on any single-seed ACDC number) stands.
- **τ passes are independent → parallelizable.** Each τ starts fresh (`set_all_masks(0)`, `prev_faith=0`) and writes `min(tao, curr)` into a `+inf`-initialised tensor; edges never removed stay `+inf`. So splitting the τ sweep across jobs and taking the **element-wise min** across partials reproduces the single-process result exactly (min is commutative/associative, `+inf` is its identity). Empirically the split differs from a single 20-τ process by the **same 0.027 / ~half the edges** as two identical single runs — i.e. within ACDC's own nondeterminism, so the split is as faithful as ACDC is to itself.
- **Tooling added:** `run_cell.py` gains `--tao-bases`/`--tao-exps`/`--partial-tag` (ACDC-only; override the bound τ via `partial()` and write uniquely-named partials to a subdir the analysis glob ignores). `experiments/merge_acdc_partials.py` min-merges a cell's partials into one canonical cache + manifest. Launchers (gitignored): `acdc_ioi_partials.sh` (5 τ-bases × 3 ablations = 15 partial jobs, splitting IOI's ~39 GPU-h over ~9 GPUs → ~5 h wall) + `acdc_ioi_merge.sh` (chained via `--dependency=afterok`). Cell-level parallelism was already maxed (9 concurrent cells); the win is spreading the IOI long-pole across more GPUs.
- **Significance:** Restores ACDC to a comparable point density and reachable sparsity on the faithfulness spine; documents ACDC's intrinsic run-to-run instability (a Pillar-2 signal, not noise to hide); and provides a validated, exact-up-to-nondeterminism parallelization for the expensive ACDC discovery.
- **Code pointer:** `auto_circuit/prune_algos/prune_algos.py` (τ config), `experiments/run_cell.py` (τ-split args), `experiments/merge_acdc_partials.py`, `acdc_ioi_partials.sh`, `acdc_ioi_merge.sh`.

### AutoCircuit's left-padded batches need BOS to be batch-invariant — 2026-08-12

- **Context:** Building the Tier B `pipeline` arm of the Edge Pruning port-fidelity study, which runs each implementation through its **own** real data path rather than feeding both the same token ids. That arm exists because the DiscoGP study's Tier B fed raw ids to both models and thereby excluded the dataloader, where a real bug was hiding.
- **Observation:** GPT-2's pad token **is** its BOS token (50256), and AutoCircuit left-pads. Comparing a padded batch against the same prompts run one at a time, on 16 ragged IOI prompts, `prepend_bos=False` gives max |Δ log p| = **2.63** (argmax agreement 96.9%) where `prepend_bos=True` gives 2.9e-05.
- **Mechanism (confirmed, not inferred):** `HookedTransformer.forward` recomputes the attention mask itself, and when handed a raw token tensor it reads `prepend_bos` from **`cfg.default_prepend_bos`** (True) rather than from however the tokens were built (`HookedTransformer.py:286-294`). `get_attention_mask` then un-masks the last leading pad on the assumption it is a prepended BOS (`transformer_lens/utils.py:976-978`). With `prepend_bos=False` there is no BOS, so a genuine pad token is re-enabled — one per row.
  - 2×2 confirmation: the gap appears **only** in the (tokens without BOS, `cfg.default_prepend_bos=True`) cell — 2.63 — against 2.5e-05, 2.1e-05 and 2.9e-05 in the other three.
  - Visible in the mask itself: a 14-token prompt padded to 20 attends **15** positions under `prepend_bos=True` and exactly 14 under `False`.
  - So this is an **AutoCircuit** defect, not a TransformerLens one: TL behaves correctly given what it is told, and AutoCircuit never threads its own `prepend_bos` through to the forward. The fix is one line (`model.cfg.default_prepend_bos = prepend_bos`), deliberately **not applied** while Tier C was in flight, since patching mid-run would leave cached cells computed under two behaviours.
- **Severity is latent, not active.** `tasks.py:215` sets `prepend_bos=has_tokenizer`, so every shipped tokenizer task passes `True` and no built-in task reaches this path. It bites only callers explicitly passing `prepend_bos=False` (i.e. the `port-nobos` arms of both port-fidelity studies), is conditional on padding being present, and touches at most one token per padded row.
- **It is the third of three distinct triggers of the same TL heuristic**, confirmed independently by the DiscoGP-study session: (a) the KV-cache prefix-constancy bug, fixed by #17/PR #18; (b) `tail_divergence` stripping splitting the leading pad run, only *avoided* on GPT-2 by declining to strip; (c) this one, caller/TL disagreement about `prepend_bos`, which lives on the ordinary forward path and would survive deleting `tail_divergence` outright.
- **Consequences:**
  - **`prepend_bos=False` is not a safe knob on ragged prompts.** It does not isolate the BOS factor, it introduces a second and larger artifact. The EP study therefore measures the BOS factor on uniform-length prompts (no padding on either side), and reports its Tier C `port-nobos` arm as an *input-convention* arm rather than a clean BOS measurement.
  - **The DiscoGP study's `port-nobos` arm carries the same confound** and its reading must be qualified identically. Its primary and control arms are unaffected: they all run with BOS.
  - Distinct from the `tail_divergence` defect (UFO-101/auto-circuit#17); that one was about a shared KV cache, this one is about padding and BOS.
- **Significance:** A second data-path hazard in the shared harness, found only because a test was deliberately built to include the code path a previous test had bypassed. Bounds one arm of both port-fidelity studies.
- **Code pointer / Run:** `tests/prune_algos/test_edge_pruning_equivalence.py::test_left_padding_needs_bos_to_be_batch_invariant`; `docs/port_validation/edge_pruning.md` §4.

### Two Edge Pruning port divergences the source audit had missed — 2026-08-12

- **Context:** Tier A/B of the EP port-fidelity study, converting `docs/related_work/edge_pruning.md`'s "faithful" column from audited-by-reading to tested.
- **Observation — mask sampling has no batch dimension in the reference.** `sample_z_from_log_alpha` (`l0.py:43-48`) draws one `u` of shape `log_alpha.shape`, on **CPU in fp32**, clamped to `(1e-6, 1−1e-6)`: one hard-concrete sample per forward, shared across the whole batch. The port's `sample_hard_concrete` draws `batch_size` **independent** samples on device, clamped to `(1e-4, 0.9999)`, then averages over the batch before computing sparsity. Two divergences in one line: a different gradient estimator (lower variance in the port) and a different support.
  - Measured as a Tier C mechanism arm (`port-sharedz`) rather than argued about.
- **Observation — the KL span difference is removable, but only conditionally.** The reference's KL is `batchmean` over the answer span then divided by batch; the port takes the last-token `out_slice`. For a **one-token** answer span these are identical, and AutoCircuit's IOI answers are single-token by construction. Tier A asserts `span == 1` for every row of the frozen split, and separately asserts the two **do** diverge on a two-token span, so the condition is documented rather than assumed.
- **Significance:** The first is a genuine remaining difference in the thesis's EP results and belongs in the limitations table; the second is a difference that the IOI benchmark happens to eliminate, which is worth stating precisely because it would *not* be eliminated on a task with multi-token answers.
- **Code pointer:** `docs/port_validation/edge_pruning.md` §1; `tests/prune_algos/test_edge_pruning_components.py`.

### EP results in this thesis are not directly comparable to the Edge Pruning paper's — 2026-08-12

- **Context:** Tier C of the EP port-fidelity study (50 matched runs, frozen IOI split, one scoring harness at k = 2000).
- **Observation:** The port and `princeton-nlp/Edge-Pruning` @ `a918efd` do **not** find equivalent circuits. Clean KL 0.142 vs 0.258 (4.5× the pre-registered margin, p = 1.1e-05), Answer Pair KL 0.051 vs 0.101 (3.9×, p = 0.0015).
- **Cause, isolated:** the reference draws one hard-concrete mask sample per forward and shares it across the batch (`l0.py:43-48`); the port draws one per example and averages. Switching the port to shared sampling moves Clean KL to 0.250 against the reference's 0.258 and flips the difference test from p = 1.1e-05 to p = 0.77.
- **Checked against the paper (2026-08-12), not assumed.** arXiv 2406.16778 §3 writes the hard-concrete draw as `u ~ Uniform(eps, 1-eps)` with **u** a vector over edges and `log alpha` element-wise. **No batch index appears anywhere** — not in those equations, not in the Lagrangian, not in Eq. 3. Appendix A gives learning rates, steps, batch sizes and sparsity targets but never the sampling granularity. So neither implementation violates a stated specification.
  - The reference's reading follows the structured-pruning lineage it cites (Wang 2020; Xia 2022, CoFi), where the mask *is* the subnetwork being produced — a property of the model, so one draw per step is natural.
  - The port's reading follows Eq. 3, which is written per example, and AutoCircuit's own wrapper convention (`patch_wrapper.py:135`, "Sample distribution for each batch element").
  - The authors never had to decide: their CodeLlama-13B runs use **batch size 1**, where the two readings coincide.
  - **So this is an unstated implementation detail on both sides — not a bug, and not a documented design choice.** It is the seam where structured pruning (one mask per subnetwork) was transplanted into interpretability (one forward per example).
- **Direction matters for how this is written up:** the port is not worse. It is *more* faithful (lower KL) and sparser at its own operating point, because averaging 32 draws per step is a lower-variance gradient estimator. So this is a comparability caveat, not a correctness defect.
- **Resolved 2026-08-12 — the port now runs EP as published.** `edge_pruning_prune_scores` gained `shared_mask_sample: bool = True` (the reference's behaviour) and the spine uses it; the per-example estimator stays available behind the flag. Rationale: the thesis compares methods and proposes improvements, so a variance-reduced EP baseline would have been compared against paper-faithful DiscoGP/ACDC/EAP, crediting the method with an improvement belonging to the port, and would have understated any later contribution by measuring it against an already-improved baseline.
  - This turns the caveat into a small **result**: the paper leaves the sampling granularity unspecified, and resolving it the other way is worth ~45% faithfulness on IOI (0.258 → 0.142 at matched sparsity). Reportable only because the baseline is the published one.
  - **Cost:** 9 Pillar-1 EP cells and 45 Pillar-2 EP cells invalidated (Pillar 3 not yet run). Pillars 1 and 3 were already due for re-run after the `data.py` fix, so the marginal cost is Pillar 2.
  - **Knock-on, now discharged (2026-08-14):** re-running Pillar 2 changed the EP port-fidelity margins, which the pre-registration required recomputing. Final values are v4 (`stability_v4_2026-08-13`): Clean KL 0.02808, Logit Diff 10.8835, Answer Pair KL 0.05500, Jaccard 0.00663 — three of four wider than v2, so equivalence became easier to declare for a reason unrelated to the port. State that direction explicitly rather than let it read as a result. Two failed attempts preceded v4; see "Two provenance controls" below.
  - EP's reported faithfulness across the thesis gets **worse**, measured: IOI resample Clean KL 0.155 → 0.260 at k = 2000. Seed stability falls too, mean pairwise Jaccard 0.622 → 0.245. Both are the correct baseline, not a regression.
  - **Still outstanding:** the ACDC/EAP/DiscoGP cells in both pillars predate these `data.py` changes, so no cross-method claim (e.g. "EP is less stable than DiscoGP") is available until they are re-run. EP's new numbers are safe only against EP's own history.
- **Significance:** Any sentence comparing this thesis's EP numbers to the paper's reported numbers must carry this caveat. It also sharpens the general point: the *cores* of both ports are exact (Tiers A and B), and the divergence that actually moved results was a one-line sampling detail that a source audit had marked "verbatim". Auditing by reading cannot find this class of difference.
- **Code pointer / Run:** `docs/port_validation/edge_pruning.md` §5.4-5.5; `results/port_fidelity/ep_tier_c*/`.

### Two provenance controls the port-fidelity study had to learn the hard way — 2026-08-14

- **Context:** re-running the 54 EP cells after the mask-sampling change. Two separate mistakes invalidated a first and then a second attempt, and both are cheap to avoid but invisible if not checked explicitly.
- **Limitation 1 — a results directory's name does not date the data inside it.** `stability_v2_2026-08-11` reads cells discovered on 08-10, at a commit that predates the 2026-08-11 `data.py` fix. Believing the folder name led to describing those margins as "post-fix" when they were not. **Check the git commit recorded in each cell's manifest (`git merge-base --is-ancestor`), never the directory name or file mtime.** Cousin of the lexical-sort cache bug of 2026-06-17.
- **Limitation 2 — hardware is a controlled variable for any seed-variance measurement.** `stability_discovery_v2.sh` pins `gpu_model:a180` and documents why: cross-architecture runs are not bit-reproducible and the difference compounds through training. The re-run script constrained on GPU *memory* instead (to dodge a 24 GB OOM) and SLURM spread the cells over four architectures: a180/ampere, a6000/ampere, l40/lovelace, titanrtx/turing. Since δ *is* a standard deviation, node variance entered the measured quantity directly.
    - **Measured cost:** the two most affected margins fell 14% and 33% once pinned (Clean KL 0.03259 → 0.02808, Logit Diff 16.36 → 10.88). Answer Pair KL moved the other way, so the inflation was not uniform and could not have been corrected by a scale factor.
    - **What it did not corrupt:** mean pairwise Jaccard moved 0.2409 → 0.2445 and no EP cell moved more than 0.028 across nine task × ablation combinations, so the structural finding survived. Hardware inflated the noise estimate without manufacturing the effect.
    - The OOM that motivated relaxing the pin was already solved by the pin, since every a180 node is 80 GB. There was no tradeoff to make.
- **Limitation 3 — an uncommitted change makes the provenance field lie in the trusting direction.** 7 cells ran the corrected `data.py` while it was still uncommitted, so their manifests recorded the *parent* commit. `dirty: True` and the filename were also recorded, so the information was recoverable by hand, but an automated ancestor check would have classified them as pre-fix. They were re-run so every cell carries `2a9c0e0`. **Commit before launching, or treat `dirty: True` as disqualifying for provenance.**
- **Significance:** none of the three is about circuit discovery, and all three would have silently changed a reported number. They are the operational counterpart to the study's own thesis, that reading code cannot establish equivalence: reading a results folder cannot establish what produced it either.
- **Code pointer / Run:** `ep_rerun.sh` (corrected pin), `ep_restamp.sh`; `docs/port_validation/edge_pruning.md` §5.2, §7.

### The port-fidelity density endpoint is mis-calibrated and its "equivalent" verdict is uninformative — 2026-08-14

- **Context:** Tier C of the EP port-fidelity study reports edge density at each implementation's own operating point, discretised by Edge Pruning's own rule (`deterministic_z` per mask tensor, not a fixed threshold).
- **Observation:** the endpoint reports `equivalent` for `port` vs `orig` while simultaneously reporting p = 1.1e-05 with a 90% CI of [−0.0137, −0.0134]. Both are correct: TOST asks only whether the CI sits inside ±δ, and δ_density = 0.02.
- **Cause:** δ_density (like δ_spearman) was chosen a priori, not derived from measured seed spread like the four primary margins. Observed densities span 0.011–0.025, so a ±0.02 absolute margin covers the entire plausible range and essentially nothing can fail it.
- **Magnitude of what it waved through:** the port keeps ~370 edges of ~32k, the reference ~800, a factor of 2.2. The implementations disagree substantially about how large a circuit to return.
- **Handling:** reported as pre-registered rather than rescaled after seeing the data, and flagged. The `equivalent` flag on this row must never be cited as fidelity support. A ratio margin, or one derived from Pillar-2 spread, would have been correct.
- **Transferable point:** an equivalence margin chosen on an absolute scale before knowing the quantity's range can be vacuous, and vacuity looks exactly like success. The negative-control discipline catches an endpoint with no power; it does not catch an endpoint with a margin too wide to fail. Density detected 2 of 3 controls, so it passed that check while still being uninformative here.
